05学习与思考 / Notes

KNOWLEDGE BASE
01

理解 Maven：从坐标、仓库到依赖范围

构建工具 / 阅读约 1 分钟

Maven 用 groupId:artifactId:version 标识一个依赖。POM 不只是一份依赖清单，也描述项目的构建方式。

学习时可以沿着“声明依赖 → 解析依赖树 → 编译 → 测试 → 打包”的顺序梳理。遇到版本冲突时，先检查依赖树，再考虑依赖管理，避免盲目叠加版本。

实践清单：理解 compile 与 test 的差异；用 dependency:tree 检查传递依赖；保证开发和构建环境使用一致的 JDK。

02

理解 Spring：IoC、DI 与分层设计

后端基础 / 阅读约 1 分钟

IoC 的核心是将对象的创建和协作交给容器管理；DI 则把一个对象所需要的依赖传递给它。理解职责关系，比记住注解更重要。

Controller 处理请求与响应，Service 组织业务逻辑，Repository 负责数据访问。层次清晰时，接口变化、业务变化和存储变化更容易分别处理。

实践清单：尝试构造器注入；为业务服务提供可替换依赖；避免在 Controller 中堆积业务逻辑。

03

后端工程思考：可维护性比生成代码更重要

工程方法 / 阅读约 1 分钟

代码能够运行只是第一步。清晰的边界、可理解的命名、稳定的接口和可以复现的问题，决定一个项目能否持续演进。

使用 AI 辅助开发时，先描述输入输出、约束与失败场景，再审查生成结果。测试应关注真实行为，尤其是无效参数、资源不可用和边界条件。

实践清单：先写接口契约；记录设计取舍；为关键路径保留验证步骤；让下一位维护者能够复现环境。
